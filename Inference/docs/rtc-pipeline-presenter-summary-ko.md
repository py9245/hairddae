# RTC 처리 흐름 요약

이 서비스는 사용자의 카메라 영상을 WebRTC로 받아서, 실시간으로 헤어를 바꾼 뒤 다시 영상으로 돌려주는 구조다. 흐름은 크게 다섯 단계다.

첫째, 프론트가 WebRTC `offer`를 보내면 서버가 연결을 열고, 제어 채널과 영상 채널을 준비한다. 제어 채널에서는 어떤 헤어를 선택했는지 같은 메시지를 주고받고, 영상 채널에서는 실제 카메라 프레임이 들어온다.

둘째, 영상 프레임이 들어오면 서버는 먼저 전처리를 한다. 여기서 얼굴 랜드마크와 헤어 세그멘테이션을 동시에 돌려 사용자의 얼굴 위치, 머리 방향, 머리카락 영역을 잡는다. 그런 다음 기존 머리를 그대로 두지 않고, 새 헤어가 자연스럽게 올라갈 수 있도록 일부를 피부색이나 배경 쪽으로 정리한 준비 프레임을 만든다.

셋째, 런타임 엔진이 현재 사용자의 얼굴 각도와 위치를 보고 가장 맞는 헤어 에셋을 고른다. 이 단계에서는 무조건 계속 바꾸지 않고, 조금 흔들리는 정도면 이전 헤어를 유지해서 화면이 덜 불안정하게 보이도록 한다.

넷째, 선택된 헤어 에셋을 사용자의 얼굴과 머리 위치에 맞춰 변형한 뒤 영상 위에 합성한다. 이때 머리카락이 얼굴을 너무 침범하지 않게 조정하고, 에셋 밖으로 삐져나온 기존 머리는 후처리로 정리한다.

다섯째, 완성된 프레임을 다시 WebRTC 영상 프레임으로 인코딩해서 사용자에게 돌려보낸다. 중요한 점은 서버가 오래된 프레임을 계속 쌓아두지 않고 최신 프레임 위주로 처리한다는 것이다. 그래서 약간의 품질 보정보다 실시간성을 우선해, 사용자가 끊김 없이 바로 결과를 보도록 설계돼 있다.

발표에서는 이렇게 설명하면 된다. “사용자 영상을 받으면, 얼굴과 머리 위치를 먼저 이해하고, 기존 머리를 정리한 뒤, 가장 잘 맞는 헤어를 골라 실시간으로 씌워서 다시 보내주는 시스템이다.”
