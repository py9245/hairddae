### 1. 초기화면 (랜딩 페이지)

**TC 1-1. 화면 렌더링 및 네비게이션 (정상)**
* **상황 (Given):** 사용자가 서비스 URL에 최초 접속했다.
* **행동 (When):** 1. '무료로 시작하기' 버튼을 클릭한다.
    2. '로그인' 버튼을 클릭한다.
* **기대 결과 (Then):** 1. '무료로 시작하기' 클릭 시 `/auth/signup` (회원가입) 페이지로 즉시 이동한다.
    2. '로그인' 클릭 시 `/auth/login` (로그인) 페이지로 즉시 이동한다.

### 2. 회원가입 페이지

**TC 2-1. 신규 회원가입 처리 (정상)**
* **상황 (Given):** 사용자가 회원가입 페이지에 있다.
* **행동 (When):** 유효한 아이디/비밀번호를 입력하고, 필수 약관에 체크한 뒤 가입 버튼을 누른다.
* **기대 결과 (Then):** 회원가입 성공 토스트(또는 모달)가 노출되며, 메인 페이지로 리다이렉트 된다.

**TC 2-2. 비밀번호 확인 불일치 (예외)**
* **상황 (Given):** 사용자가 회원가입 폼을 작성 중이다.
* **행동 (When):** '비밀번호'와 '비밀번호 확인' 필드에 서로 다른 값을 입력한다.
* **기대 결과 (Then):** 즉시 하단에 붉은색 텍스트로 '비밀번호가 일치하지 않습니다' 에러 메시지가 노출되며, 회원가입 버튼이 비활성화(Disabled) 상태가 된다.

**TC 2-3. 필수 약관 미동의 (예외)**
* **상황 (Given):** 사용자가 모든 정보를 입력했다.
* **행동 (When):** 필수 약관 동의 체크박스를 해제한 상태로 가입 버튼을 클릭하려 한다.
* **기대 결과 (Then):** 가입 버튼이 비활성화되어 클릭할 수 없거나, 클릭 시 '필수 약관에 동의해주세요'라는 피드백이 제공된다.

### 3. 로그인 페이지

**TC 3-1. 정상 로그인 (정상)**
* **상황 (Given):** 사용자가 로그인 페이지에 있다.
* **행동 (When):** 올바른 계정 정보를 입력하고 로그인 버튼을 클릭한다.
* **기대 결과 (Then):** 로그인 로딩 스피너가 잠시 돌고, 성공적으로 인증 토큰을 받아 메인 페이지(`/main`)로 이동한다.

**TC 3-2. 잘못된 계정 정보 입력 (예외)**
* **상황 (Given):** 사용자가 로그인 페이지에 있다.
* **행동 (When):** 존재하지 않는 아이디나 틀린 비밀번호를 입력하고 로그인 버튼을 누른다.
* **기대 결과 (Then):** 입력 필드 테두리가 붉은색으로 변하거나, '아이디 또는 비밀번호가 올바르지 않습니다.'라는 에러 메시지가 폼 하단에 노출된다.

### 4. 구글 로그인 페이지

**TC 4-1. 구글 OAuth 로그인(정상)**
* **상황 (Given):** 사용자가 로그인 페이지에 있다.
* **행동 (When):** 구글 로그인 버튼을 클릭한 후 구글 계정으로 로그인을 한다.
* **기대 결과 (Then):** 성공적으로 인증 토큰을 받아 메인 페이지(`/main`)로 이동한다.

**TC 4-2. 구글 OAuth 로그인 실패 (예외)**
* **상황 (Given):** 사용자가 로그인 페이지에 있다.
* **행동 (When):** 구글 로그인 버튼을 클릭한 후 잘못된 구글 계정으로 로그인을 한다.
* **기대 결과 (Then):** 구글 로그인 실패로, 로그인이 안 된다.


### 5. 메인 페이지

**TC 5-1. 헤어 리스트 정렬 (정상)**
* **상황 (Given):** 메인 페이지에 추천 헤어 리스트가 렌더링 되어 있다.
* **행동 (When):** '인기순' 탭과 '최신순' 탭을 번갈아 클릭한다.
* **기대 결과 (Then):** 페이지 새로고침 없이 리스트의 배열 순서가 해당 기준에 맞게 즉각적으로 재렌더링된다.

**TC 5-2. 카메라 페이지 진입 (정상)**
* **상황 (Given):** 사용자가 마음에 드는 헤어스타일을 발견했다.
* **행동 (When):** 특정 헤어스타일 카드의 '적용하기' 버튼을 클릭한다.
* **기대 결과 (Then):** 선택한 헤어스타일의 고유 ID를 상태로 유지한 채 카메라 페이지로 화면이 전환된다.

### 6. 카메라 페이지

**TC 6-1. 카메라 권한 허용 및 실시간 적용 (정상)**
* **상황 (Given):** 사용자가 메인 페이지에서 헤어를 선택하고 카메라 페이지로 넘어왔다.
* **행동 (When):** 브라우저의 카메라 접근 권한 요청 팝업에서 '허용'을 클릭한다.
* **기대 결과 (Then):** 디바이스 카메라가 켜지며 화면에 사용자 얼굴이 보이고, 그 위에 메인 화면에서 선택했던 헤어스타일이 실시간으로 오버레이되어 렌더링된다.

**TC 6-2. 캡처 및 저장 플로우 (정상)**
* **상황 (Given):** 카메라 뷰에 헤어스타일이 적용된 상태다.
* **행동 (When):** 1. 하단 촬영 버튼(흰색 동그라미)을 클릭한다.
    2. 화면이 일시정지된 상태에서 '다운로드' 버튼을 다시 한번 클릭한다.
* **기대 결과 (Then):** 
    1. 캡처 시 화면이 멈추고, 캡쳐 버튼이 다운로드 버튼으로 변경된다
    2. 저장 클릭 시 다음과 같다.
        - 브라우저 : 우측 상단에 다운로드 완료 표시가 나타단다.
        - 모바일 : 
            - 아이폰 : 다운로드 후 바로 파일 다운로드 화면으로 표시
            - 갤럭시 : 하단에 다운로드가 완료됐다고 모달이 표시된다.

**TC 6-3. 실시간 헤어스타일 변경 (정상)**
* **상황 (Given):** 사용자가 카메라 화면을 보고 있다.
* **행동 (When):** 하단에 제공된 다른 헤어스타일 썸네일을 클릭한다.
* **기대 결과 (Then):** 카메라 화면에 새로고침이 없이 변경 중이라는 모달이 나오고 머리 위에 씌워진 헤어스타일 에셋만 새로운 것으로 교체된다.

### 7. 마이 페이지

**TC 7-1. 사용자 데이터 조회 (정상)**
* **상황 (Given):** 사용자가 마이 페이지에 진입한다.
* **행동 (When):** 화면을 스크롤하여 내용을 확인한다.
* **기대 결과 (Then):** 서버에서 불러온 '최근 적용한 헤어'와 '찜한 헤어스타일' 리스트가 정상적으로 렌더링되며, 적용하기 버튼 클릭 시 해당 헤어가 적용된 카메라 페이지로 이동할 수 있다.

**TC 7-2. 로그아웃 기능 (정상)**
* **상황 (Given):** 사용자가 로그인된 상태다.
* **행동 (When):** 마이 페이지 내의 '로그아웃' 버튼을 클릭한다.
* **기대 결과 (Then):** 로컬 스토리지(또는 쿠키)에 저장된 사용자 인증 토큰이 삭제되고, 서비스 초기화면(스플래시 페이지)으로 강제 리다이렉트 된다. 이후 브라우저 '뒤로가기'를 눌러도 마이 페이지로 진입할 수 없다.
