## 작업 요약
- `hairapplystart`가 단순 UUID 반환에 그치지 않도록 작업 저장소를 추가했다.
- `HairApplyJobRepository`를 도입해 JPA 사용 가능 환경에서는 `jobs` 테이블에 작업을 저장하고, 테스트 프로필에서는 인메모리 fallback으로 동작하게 구성했다.
- `hairapplystart` 호출 시 `jobType=HAIR_APPLY`, `status=PENDING`, 요청 `hairID`를 담아 작업을 생성하고 작업 ID를 반환하도록 변경했다.
- 신규 상태 조회 API `/api/home/hairapplystatus/{applySessionId}`를 추가했다.
- 상태 조회는 작업 ID 기준으로 `jobType`, `status`, `hairID`, `completedAt`을 반환하고, 다른 사용자의 작업 접근은 차단한다.
- 통합 테스트에 시작 후 상태 조회가 가능한 흐름을 추가했다.
